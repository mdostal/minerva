Where it fits in Pantheon

Minerva runs the front half of the agentic SDLC loop (kickoff + plan), autonomously building specs while routing human-gate questions to the decision surface. Splitting the planner out of a single terminal window allows Pantheon to process many ideas in parallel.

1. Receive (Auriga)

Auriga acts as the router. When an idea arrives, Auriga spawns a Minerva subprocess to handle the planning phase, passing off the raw idea.

2. Plan & Ask (Minerva)

Minerva drives plugin-hive planning skills, hitting human-in-the-loop gates. Instead of halting in a terminal, it delegates questions to the decision surface.

3. Decide (Surface)

Humans answer strategy and design questions on the Delphi/Consus decision surface. When answered, Minerva resumes the run.

4. Provision & Build (Vulcan & Swarm)

With an approved epic, Vulcan provisions repositories and Auriga dispatches the execution swarm to write the code.

Architecture & Flow

Minerva's public interface is a JSON-over-stdio Subprocess ABI. Every call is a fresh process. Run state persists on the filesystem under ~/.minerva/runs. There is no daemon — a run only advances when a caller invokes submitAnswers.

Quickstart

Minerva requires Node.js >=20.19. One JSON request in on stdin, one JSON response out on stdout. No server to start.

npm install

# Discover the ABI version
echo '{"method":"capabilities"}' | npx tsx bin/minerva.ts

# Start a run from an idea (returns a run_id)
echo '{"method":"startRun","params":{"idea":"add SSO to billing"}}' | npx tsx bin/minerva.ts

# Pull the pending questions for a run
echo '{"method":"getQuestions","params":{"run_id":"<run_id>"}}' | npx tsx bin/minerva.ts

# Answer them (advances the run)
echo '{"method":"submitAnswers","params":{"run_id":"<run_id>","answers":[...]}}' | npx tsx bin/minerva.ts

# Fetch the approved epic + stories
echo '{"method":"getOutput","params":{"run_id":"<run_id>"}}' | npx tsx bin/minerva.ts
